# Отчёт о выполнении лабораторной работы №2

## Постановка задачи

В рамках задания требовалось модифицировать существующий компонент CEcoLab1, добавив функциональность калькулятора через механизмы включения и агрегирования. Основная цель заключалась в интеграции компонентов калькуляторов A, B, C, D, E с демонстрацией работы интерфейсов IEcoCalculatorX и IEcoCalculatorY, а также реализации алгоритма сортировки пузырьком.

## Реализованная архитектура

Была успешно реализована гибридная схема, сочетающая агрегирование и включение компонентов. Для интерфейса IEcoCalculatorX компонент CEcoLab1 использует приоритетную систему загрузки:

- **Первый приоритет**: CalculatorB с агрегированием через внешний Unknown
- **Второй приоритет**: CalculatorA с простым включением  
- **Третий приоритет**: CalculatorC с простым включением

Для интерфейса IEcoCalculatorY реализовано последовательное включение компонентов CalculatorC, CalculatorD и CalculatorE.

Механизм агрегирования реализован через расширенную функцию QueryInterface в CEcoLab1, которая делегирует запросы к интерфейсам IEcoCalculatorX и IEcoCalculatorY соответствующим внутренним компонентам. Это позволяет клиентам работать с интерфейсами калькуляторов напрямую через основной компонент.

## Функциональность компонента

Компонент CEcoLab1 предоставляет два основных интерфейса:

### IEcoLab1:
- `BubbleSort` - реализация алгоритма сортировки пузырьком с оптимизацией
- `ArrayGen` - генерация тестовых массивов для сортировки

### IEcoCalculatorX и IEcoCalculatorY:
- `Addition` и `Subtraction` - операции сложения и вычитания через IEcoCalculatorX
- `Multiplication` и `Division` - операции умножения и деления через IEcoCalculatorY

Операции калькулятора делегируются внутренним компонентам с учетом приоритетов загрузки. При этом операции сложения и вычитания выполняются через IEcoCalculatorX (CalculatorB, CalculatorA или CalculatorC), а умножение и деление — через IEcoCalculatorY (CalculatorC, CalculatorD или CalculatorE).

## Особенности реализации

1. **Гибридная модель агрегирования**: CalculatorB загружается с агрегированием, остальные компоненты - с простым включением
2. **Полная поддержка QueryInterface**: Реализованы цепочки преобразования между всеми интерфейсами: IEcoLab1, IEcoCalculatorX, IEcoCalculatorY и IEcoUnknown
